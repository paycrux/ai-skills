## `####` 판단 근거 블록 톤 비교

리뷰어는 이 코드를 직접 짜지 않았다. 구현자만 아는 용어를 던지면 그 문단은 읽히지 않는다.

**이렇게 쓰지 않는다**

> 목록 조회는 `@ModelAttribute`라 생성 타입이 중첩 객체다. 기본 deepObject 직렬화로 부르면 400이 아니라 200에 전건이 돌아온다. 그래서 필터 시나리오는 요청 URL을 파싱해 배열이 반복 파라미터로 나가는지를 단언한다.

읽는 사람이 `deepObject 직렬화`, `반복 파라미터`가 뭔지 모르면 아무것도 전달되지 않는다.

**이렇게 쓴다**

> 필터를 걸어도 서버가 조건을 무시한 채 전체 목록을 정상 응답으로 돌려준다. 응답만 보면 성공으로 보여서, 요청 URL에 검색어와 카테고리가 실제로 실렸는지를 대신 확인한다.

배경(무시된다) → 왜 문제인지(성공처럼 보인다) → 그래서 뭘 했는지 순서. 세 문장이 넘어가면 블록을 쓰지 말고 위 bullet 한 줄로 접는다.
