[tracker] {이슈 키} {제목} 작업을 맡아 주세요 — 계획부터 기기 확인 체크리스트까지 이 세션에서 진행합니다.

- 메타 플랜: `{메타 플랜 절대경로}` — 읽기만 하세요. tracker만 씁니다.
- 이슈: {이슈 키} (부모 스토리 {스토리 키})
- 워크트리: `{워크트리 경로}` / 브랜치 `{브랜치}` (갈라진 곳 `{갈라진 곳}`)
- 루트 `{루트}`에는 커밋·푸시·강제 푸시를 하지 마세요.

순서

1. `/task-plan` — 입력: 메타 플랜 `{메타 플랜 절대경로}`의 {이슈 키}. 메타 플랜의 "{스토리 블록 제목}"에서 이 이슈 몫의 기획 발췌·문구·디자인 노드·미정을 기획 원본으로 씁니다. 계획 검토는 이 탭에서 사용자와 합니다.
2. 사용자가 계획을 승인하면 `/implement`.
3. 막히는 질문은 해당 항목에 `**blocker**`를 표시하고, 할 수 있는 것부터 진행한 뒤 이 탭에서 사용자에게 직접 묻습니다. tracker로 보내지 마세요.
4. 형제 이슈도 쓸 것이 필요해지면 직접 만들지 말고, 해당 항목에 `**blocker**: 스토리 공용 — {무엇}`을 표시한 뒤 tracker에 `[공용 필요] {이슈 키} — {무엇}` 한 줄을 보냅니다.
5. 구현이 끝나면 바로 커밋합니다. 크면 Phase 단위로 나눕니다. 커밋 메시지는 전역 규칙(한국어, `feat:` 등 접두사)대로.
6. RN 앱이면 `/implement`가 `tasks.md`에 `## 기기 확인` 체크리스트를 씁니다. 웹이면 `/qa`.
7. 공유 컴포넌트(`components/ui/*` 등)는 고치지 말고 차이만 보고합니다.
8. 끝나면 tracker(`{tracker 세션 이름}`)에 아래 형식으로 보냅니다.

```
[결과] {이슈 키}
- 커밋: {해시} {제목} (여러 개면 줄마다)
- 구현: {한두 줄}
- 미결: {구현 영향 없음으로 남은 질문 — 없으면 "없음"}
- 공유 컴포넌트 차이: {있으면}
```
